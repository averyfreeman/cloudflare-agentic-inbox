# Project Process and Key Milestones

Work backwards from the desired deployed end state. Each milestone must have a real verification command or observable artifact before moving on.

## Milestone 0 — Preserve context and establish safety

1. Read `.hermes.md` and these reminder files before each substantial work session.
2. Inspect Git status and existing branches before editing.
3. Confirm `.gitignore` protects `.env`, `.env.*`, credentials, local state, and test artifacts.
4. Inventory the repository, neighboring Cloudflare resources/documentation, and available tooling without exposing credentials.
5. Identify missing specifications in `.env.local` and missing secret values in `.env` without printing either file.

Exit evidence: clean understanding of current project state, protected secrets, and a written list of blockers/questions.

## Milestone 1 — Baseline application health

1. Install dependencies with the repository's package manager.
2. Run the existing typecheck, build, lint/test scripts, and Wrangler validation.
3. Read failures fully and classify them as source, dependency, environment, binding, or deployment problems.
4. Establish tight reproductions for each blocker before changing code.

Exit evidence: baseline commands and exact failures recorded; application build either passes or has isolated blockers.

## Milestone 2 — Configuration and bindings

1. Replace placeholder domain configuration only with an explicitly supplied specification.
2. Ensure the Worker bindings match the source code: Durable Objects, SQLite migrations, R2, Workers AI, and Email Service.
3. Check whether the requested infrastructure is D1 or Durable Object SQLite. The current repository architecture uses Durable Object SQLite; do not silently introduce D1 unless the final specification requires it.
4. Prepare non-secret variables through `.env.local` and secrets through Wrangler secret commands or the approved deployment mechanism.
5. Confirm resource names and account/zone context before creation.

Exit evidence: a reviewed `wrangler.jsonc`, binding/type generation succeeds, and required resources are either present or have explicit creation commands.

## Milestone 3 — Build and local runtime

1. Compile the Worker/UI with `npm run build`.
2. Run `npm run typecheck` and relevant tests.
3. Start the local dev server and verify health, UI rendering, API routes, mailbox operations, and agent panel behavior.
4. Exercise the browser through Playwright/Chrome at `127.0.0.1:9222` when available, prioritizing user-visible flows over obscure unit cases.
5. Fix root causes one at a time and rerun the tight test loop after each change.

Exit evidence: reproducible local build, passing focused browser checks, and no known blocker on the primary UI/API paths.

## Milestone 4 — Cloudflare resource provisioning

1. Authenticate/verify Wrangler account context without exposing tokens.
2. Create or confirm the R2 bucket.
3. Deploy Durable Object migrations using the configured migration tags.
4. Confirm Workers AI and Email Service availability.
5. Configure Email Routing to send inbound mail to the Worker.
6. Configure Cloudflare Access and capture the required secret values securely.
7. Configure DNS/custom domain only after the zone and route are confirmed.

Exit evidence: Cloudflare resource identifiers/status and a deployment-ready binding configuration.

## Milestone 5 — First deployment

1. Run the final local checks.
2. Deploy with Wrangler using the intended environment.
3. Capture the Worker name, deployment version, URL, resource bindings, and command output without exposing secrets.
4. Confirm the production Access policy is enabled and the unauthenticated path fails closed.
5. Open the authenticated application and verify the UI.

Exit evidence: real deployment ID/version and reachable protected URL.

## Milestone 6 — End-to-end email and agent verification

1. Create/configure the mailbox for `avery@unixgreybeard.org`.
2. Send a controlled inbound test message from an approved test sender.
3. Verify Email Routing → Worker → Durable Object SQLite → UI.
4. Verify attachment storage and retrieval through R2.
5. Verify the agent can read/search/draft while requiring confirmation before send.
6. Send a controlled outbound reply through Email Service.
7. Verify headers, recipient, sender, threading, and delivery status.
8. Confirm MCP and agent access respect the documented Access trust boundary.

Exit evidence: recorded pass/fail results for each primary flow, with no secret or message body leakage in logs.

## Milestone 7 — Creative extension and hardening

Only after the core path works, add one focused extension that improves the product and is supportable. Examples include safe external context enrichment, stronger agent reasoning, or improved audit/observability. The extension must have tests, a configuration switch, and a rollback path.

Exit evidence: extension-specific test and deployment behavior documented.

## Milestone 8 — Final report and handoff

1. Re-run build, typecheck, browser checks, and deployment smoke tests.
2. Record current Git diff/status and generated files.
3. Write a final markdown summary with actual commands/results, deployment URL/version, resource names, manual Cloudflare/Google Workspace steps, known limitations, and rollback instructions.
4. Do not claim complete deployment until inbound and outbound email are verified.

## Operational loop

For every failure: reproduce → read full error → trace data flow → compare working patterns → form a falsifiable hypothesis → change one thing → rerun the tight loop → expand validation. Never replace credentials or deploy repeatedly without identifying the failing layer.

## Dependency on future specifications

The final values in `.env.local` may change domain, routing, auth, provider, test recipients, or feature requirements. Re-read the relevant variables before each deployment attempt, and never invent missing production values.
